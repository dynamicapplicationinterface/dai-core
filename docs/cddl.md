# CDDL and byte vectors

Every structure in the format that is not plain JSON, written in CDDL
(RFC 8610), with a frozen byte vector for each so an implementer can check
their encoder against bytes rather than against prose. The vectors are in
`conformance/vectors.json`, regenerated by `npm run conformance` and stable:
they are built from fixed inputs, so a change to them is a change to the
format and shows up as a diff.

Where this document and the specification disagree, the specification wins.
Where a vector and this document disagree, the vector wins: it is what two
implementations actually have to agree on.

## The CBOR profile

Everything below is deterministically encoded CBOR (RFC 8949 §4.2.1), with
three restrictions the format adds because it needs no more:

```cddl
; Only these major types appear. No floats, no indefinite lengths, and
; no tags except the one COSE_Sign1 wrapper of §9.4.
dai-value = uint / nint / bstr / tstr / [* dai-value] / {* dai-value => dai-value} / null
```

A writer MUST use the shortest length form that fits, MUST sort map keys by
their encoded bytes, and MUST NOT emit indefinite lengths. Two encoders that
agree on the values and disagree on the bytes produce signatures that do not
verify, which is the whole reason this is pinned.

## The signed payload (§3.1, §9.3)

What the publisher's signature is computed over. Rebuilt by a verifier from
the manifest it holds, never taken from the envelope.

```cddl
signed-payload = {
  "manifestVersion"      => uint,          ; 2 or 3
  "documentUuid"         => tstr,          ; canonical lowercase UUID
  "appName"              => tstr,
  "favicon"              => tstr,          ; "" when the manifest omits it
  "createdAt"            => tstr,          ; ISO 8601, as the manifest carries it
  "algorithm"            => tstr,          ; "SHA-256"
  "integrityPolicy"      => tstr,          ; "required" / "advisory"
  "signatureAlgorithm"   => tstr,          ; "COSE-ES256", or "" when unsigned
  "publicKeyFingerprint" => tstr,          ; 16 lowercase hex, or ""
  "entries"              => entry-digests,
  ? "validUntil"         => uint,          ; Unix seconds, only when set
  ? "publisherName"      => tstr,          ; version 3, only when set
  ? "supersedes"         => tstr,          ; version 3, only when set
  ? "generator"          => generator,     ; version 3, only when set
}

entry-digests = { * tstr => tstr }         ; entry name => 64 lowercase hex

generator = {
  "tool"       => tstr,
  ? "model"    => tstr,
  ? "provider" => tstr,
}
```

An optional field that the manifest omits MUST be absent from the payload, not
encoded as null or as an empty string. `favicon`, `signatureAlgorithm` and
`publicKeyFingerprint` are the exceptions: they are always present, and empty
when the manifest omits them. That asymmetry is historical and is what every
signature made so far depends on.

## The signature envelope (§3.1, §9.4)

```cddl
; RFC 9052 COSE_Sign1, untagged on write, tag 18 accepted on read (§9.4).
dai-sign1 = [
  protected   : bstr .cbor header-map,
  unprotected : { ? 11 => countersignature / [+ countersignature] },
  payload     : null,                      ; detached: rebuilt from the manifest
  signature   : bstr .size 64,             ; ES256, IEEE P1363 (r || s)
]

header-map = {
  1 => -7,                                 ; alg: ES256
  ? 4 => bstr,                             ; kid: publicKeyFingerprint, its 16 hex
}                                          ;   characters as ASCII, not the bytes they name

; The bytes actually signed (RFC 9052 §4.4).
sig-structure = [
  "Signature1",
  body_protected : bstr,
  external_aad   : bstr .size 0,
  payload        : bstr,                   ; the signed payload above, encoded
]
```

### Countersignature (§9.4)

```cddl
countersignature = [
  protected   : bstr .cbor countersign-header,
  unprotected : {},
  signature   : bstr .size 64,
]

countersign-header = {
  1 => -7,                                 ; alg: ES256
  4 => bstr,                               ; kid, required for a countersigner
}

; RFC 9338 §3.3, version 2.
countersign-structure = [
  "CounterSignatureV2",
  body_protected : bstr,                   ; the publisher's protected header
  sign_protected : bstr,                   ; the countersigner's
  external_aad   : bstr .size 0,
  payload        : bstr,                   ; the same signed payload
  other_fields   : [ bstr ],               ; [ the publisher's signature ]
]
```

## The inline carrier (§1.1)

The fragment is `base64url( carrier-header || deflate(carrier-map) )`, where
the deflate stream uses the preset dictionary the header names.

```
carrier-header = version:1 byte || dictionary-id:4 bytes
```

`dictionary-id` is the first four bytes of the SHA-256 of the dictionary,
which is what lets a reader say "I do not hold that one" rather than inflating
against the wrong table (§1.1). The dictionary itself is published beside the
suite as `conformance/inline-dictionary.bin`.

```cddl
carrier-map = {
  1     => bstr .size 16,                  ; documentUuid, raw
  2     => tstr,                           ; appName
  3     => tstr,                           ; favicon
  4     => tstr,                           ; createdAt
  5     => 0 / 1,                          ; integrityPolicy: 1 = required
  ? 6   => uint,                           ; validUntil
  ? 7   => bstr .size 33,                  ; publisher key, compressed P-256 point
  ? 8   => bstr .size 64,                  ; the publisher signature, raw
  9     => [+ carrier-entry],              ; in archive order
  ? 10  => tstr,                           ; publisherName
  ? 11  => bstr .size 16,                  ; supersedes, raw
  ? 12  => uint,                           ; manifestVersion; absent means 2
  ? 13  => [tstr, tstr, tstr],             ; generator: tool, model, provider ("" for absent)
}

carrier-entry = [name: tstr, carried: 0, bytes: bstr]
              / [name: tstr, elided:  1, digest: bstr .size 32]
```

Only `runtime/container.html`, `app/dai-kit.js`, `runtime/sqlite3.wasm` and
`runtime/sqlite3.mjs` may be elided. `identity` and countersignatures never
travel in a link.

## The sectioned footer (§2)

Not CBOR. Little-endian, the last 64 bytes of the file.

```
+0   generation   u64     increments on every save
+8   dataDigest   32      SHA-256 of section 3
+40  reserved     20      MUST be zero
+60  magic        4       00 49 41 44
```

## The bridge envelope (§4.5)

Not CBOR: structured-clone objects over `postMessage`. Written here because
two implementations of a host have to agree on the field names.

```cddl
; Container to host.
bridge-out = handshake / save / refused / timing / used

handshake = {
  "type"    => "DAI_HOST_HANDSHAKE",
  "payload" => {
    "bridgeVersion"      => 1,
    "sessionNonce"       => tstr,          ; unpredictable, invented at boot
    "documentUuid"       => tstr / null,
    "verified"           => bool,
    "payloadFingerprint" => tstr,
    "timings"            => { * tstr => uint },
  },
}

save = {
  "type"         => "DAI_HOST_SAVE",
  "sessionNonce" => tstr,
  "requestId"    => tstr,
  "payload"      => {
    "html"          => tstr,
    "databaseBytes" => bstr,
    "documentUuid"  => tstr,
  },
}

refused = {
  "type"    => "DAI_HOST_REFUSED",
  "payload" => {
    "bridgeVersion" => 1,
    "sessionNonce"  => tstr,
    "reason"        => tstr,               ; a name from §7.2
    "message"       => tstr,
    "detail"        => tstr,
    ? "documentUuid" => tstr,
  },
}

; Host to container. The acknowledgement is what makes a host present.
bridge-in = {
  "type"    => "DAI_HOST_HANDSHAKE_ACK",
  "payload" => {
    "sessionNonce" => tstr,                ; the container's own value, echoed
    "hostClass"    => "viewer" / "editor", ; absent means viewer (§4.6)
    "applied"      => [* tstr],            ; the §4 clauses this host applies
  },
} / {
  "type"      => "DAI_HOST_SAVE_ACK",
  "requestId" => tstr,
  "status"    => "ok" / "error",
  ? "error"   => tstr,
}
```

A container MUST ignore any of these that did not come from its own parent, and
a host any that did not come from the frame it mounted. `sessionNonce` binds a
message to the handshake it belongs to; it authenticates nothing (§4.5).
