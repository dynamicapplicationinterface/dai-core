### What changed, and the anchor that required it

All in `src/admit.rs`.

- **Equivocators.** Any author with an equivocated id is an equivocator. Her
  `_dai_seat`, `_dai_binding`, `_dai_confirm` and `_dai_close` rows count for
  nothing: no head, hide no row, confirm and close nobody (new verdict
  `Nothing`). Author-table rows keep the old per-id rule. `#equivocator`,
  `#heads-roster`.
- **Creator.** The hashing, undeleted `_dai_seat` row names the creator only
  when its author is not an equivocator. Before, the reader only skipped the
  row when that row's own id was equivocated. `#creator`.
- **Void sessions.** When the author of that row is an equivocator, the
  session is void, whether or not the row counts. No author-table row in it is
  admitted or reported (new verdict `VoidSession`, checked before the crossing
  rules so a crossing child is silent too). It has no holders and no voided
  seats, and nothing closes it. `#session-void`, `#report-silent`.
- **Session from the creator's row.** In her own session, the creator's roster
  rows below her creator's seat row's seq count for nothing. That covers heads,
  confirms and closes, and minting. `#session-from-creator-row`, `#confirms`.
- **A seat is a row.** Each value belongs to the `_dai_seat` entity whose
  version named it first. The versions counted are hers, in the session, at or
  above her creator's row, in her seq order, deleted or not. A confirm binds to
  the row that owns the value it names. Holders are tracked per row: one holder
  holds the row under the values the counting confirms name. Two or more
  holders void the row, and `# voided` then lists every value the row owns.
  `void_rests` is now keyed by value and carries the row's confirms.
  `#seat-is-row`, `#held-row-frozen`, `#holders`, `#void`.
- **Minting.** Only the first `max_parties` entities mint, in order of each
  entity's lowest qualifying seq, counted from the creator's row (which is
  first). A confirm counts only if the row that owns its value is minted and is
  not the creator's own row. `#confirm-minted`, `#confirms`.
- **Seated admission.** A row's seat value is looked up under `(session,
  value)` holders:
  - held by the row's author: admitted, as before;
  - held by another author: `SEAT_NOT_HELD`;
  - otherwise, if the value's row is held by another author:
    `SEAT_NOT_HELD`;
  - else silent (waiting, void, unminted, or an old value of the author's
    own held row).

  `#admitted-seat`, `#holders`.

The `#code-digest-mismatch` clauses (reported about the row's author, not in
accusation) needed no change. The reader already filed `BATCH_DIGEST_MISMATCH`
in the row author's name under the header the row names.

### Silences and ambiguities, and the reading taken

1. **`max_parties` is not in the database.** The page says it comes from the
   signed manifest, which this reader never sees. The reader hard-codes 2, from
   the page's Conformance section ("all of them are `max_parties=2` and
   `close=any`"), the same way it already treats `close=any`. A fixture with
   another bound would need the declaration carried somewhere a reader can
   read it, the way `_dai_seat_rules` is.
2. **Old value of a held row, when the author does not hold that row.**
   `#holders` says such a value "acts for nothing". It doesn't say whether a
   row naming it, by an author other than the row's holder, is
   `SEAT_NOT_HELD` (`#seat-not-held`: "a seat someone else holds") or silent.
   The reader reports it, because the seat is a row and someone else holds that
   row. When the author is the row's holder, the reader stays silent. **No
   fixture pins this.** Flipping it to silent still passes 71 of 71.
3. **What "later version" in `#held-row-frozen` changes.** Under
   `#seat-is-row`, a version already mints no new seat, and a confirm naming
   its value is already a confirm of the same row. So the reader treats a
   version of a held row the same as a reseat. The row's holder holds it only
   under the values that counting confirms name. The reader never computes
   "later than the first counting confirm". The clause adds no rule here, so
   if it was meant to say something the other anchors don't, the page doesn't
   say it.
4. **Values the creator's seat holds.** `#creator-seat` says her seat is "that
   row's `seat`". The reader gives her only the creator row's value, not values
   from later versions of her own seat row. No fixture versions the creator's
   row.
5. **Deleted versions and ownership.** `#confirm-minted` says "deleted or not"
   for the entities. The reader also lets a deleted version claim a value for
   its row. The page doesn't say this per version.
6. **Roster heads in a void session.** `#session-void` says "no row in a void
   session is admitted". `#parent-equivocated-outside` says admission belongs
   only to the author tables. So roster rows in a void session still head by
   `#heads-roster`, minus the equivocator's. `session-creator-equivocates-*`
   agrees: Bo's binding is a head.
7. **A deleted creator's row by an equivocator.** `#session-void` defines the
   creator for voiding as the author of that row "not deleted". If the hashing
   row is deleted, the session has no creator and is not void, even if its
   author is an equivocator.
8. **Creator's author-table rows below her creator's row.**
   `#session-from-creator-row` names only the roster tables. The reader leaves
   her author-table rows to the ordinary admission rules.

### Fixtures that disagree with the page
