### What changed, and the anchor that required it

All in `src/admit.rs`.

- **Equivocators.** Any author with an equivocated id is an equivocator. Her
  `_dai_seat`, `_dai_binding`, `_dai_confirm` and `_dai_close` rows count for
  nothing: no head, hide no row, confirm and close nobody (new verdict
  `Nothing`). Author-table rows keep the old per-id rule. `#equivocator`,
  `#heads-roster`.
- **Creator.** The hashing, undeleted `_dai_seat` row names the creator only
  when its author is not an equivocator. Before, the reader only skipped the
  row when that row's own id was equivocated. `#creator`.
- **Void sessions.** When the author of that row is an equivocator, the
  session is void, whether or not the row counts. No author-table row in it is
  admitted or reported (new verdict `VoidSession`, checked before the crossing
  rules so a crossing child is silent too). It has no holders and no voided
  seats, and nothing closes it. `#session-void`, `#report-silent`.
- **Session from the creator's row.** In her own session, the creator's roster
  rows below her creator's seat row's seq count for nothing. That covers heads,
  confirms and closes, and minting. `#session-from-creator-row`, `#confirms`.
- **A seat is a row.** Each value belongs to the `_dai_seat` entity whose
  version named it first. The versions counted are hers, in the session, at or
  above her creator's row, in her seq order, deleted or not. A confirm binds to
  the row that owns the value it names. Holders are tracked per row: one holder
  holds the row under the values the counting confirms name. Two or more
  holders void the row, and `# voided` then lists every value the row owns.
  `void_rests` is now keyed by value and carries the row's confirms.
  `#seat-is-row`, `#held-row-frozen`, `#holders`, `#void`.
- **Minting.** Only the first `max_parties` entities mint, in order of each
  entity's lowest qualifying seq, counted from the creator's row (which is
  first). A confirm counts only if the row that owns its value is minted and is
  not the creator's own row. `#confirm-minted`, `#confirms`.
- **Seated admission.** A row's seat value is looked up under `(session,
  value)` holders:
  - held by the row's author: admitted, as before;
  - held by another author: `SEAT_NOT_HELD`;
  - otherwise, if the value's row is held by another author:
    `SEAT_NOT_HELD`;
  - else silent (waiting, void, unminted, or an old value of the author's
    own held row).

  `#admitted-seat`, `#holders`.

The `#code-digest-mismatch` clauses (reported about the row's author, not in
accusation) needed no change. The reader already filed `BATCH_DIGEST_MISMATCH`
in the row author's name under the header the row names.

### Silences and ambiguities, and the reading taken

1. **`max_parties` is not in the database.** The page says it comes from the
   signed manifest, which this reader never sees. The reader hard-codes 2, from
   the page's Conformance section ("all of them are `max_parties=2` and
   `close=any`"), the same way it already treats `close=any`. A fixture with
   another bound would need the declaration carried somewhere a reader can
   read it, the way `_dai_seat_rules` is.
2. **Old value of a held row, when the author does not hold that row.**
   `#holders` says such a value "acts for nothing". It doesn't say whether a
   row naming it, by an author other than the row's holder, is
   `SEAT_NOT_HELD` (`#seat-not-held`: "a seat someone else holds") or silent.
   The reader reports it, because the seat is a row and someone else holds that
   row. When the author is the row's holder, the reader stays silent. **No
   fixture pins this.** Flipping it to silent still passes 71 of 71.
3. **What "later version" in `#held-row-frozen` changes.** Under
   `#seat-is-row`, a version already mints no new seat, and a confirm naming
   its value is already a confirm of the same row. So the reader treats a
   version of a held row the same as a reseat. The row's holder holds it only
   under the values that counting confirms name. The reader never computes
   "later than the first counting confirm". The clause adds no rule here, so
   if it was meant to say something the other anchors don't, the page doesn't
   say it.
4. **Values the creator's seat holds.** `#creator-seat` says her seat is "that
   row's `seat`". The reader gives her only the creator row's value, not values
   from later versions of her own seat row. No fixture versions the creator's
   row.
5. **Deleted versions and ownership.** `#confirm-minted` says "deleted or not"
   for the entities. The reader also lets a deleted version claim a value for
   its row. The page doesn't say this per version.
6. **Roster heads in a void session.** `#session-void` says "no row in a void
   session is admitted". `#parent-equivocated-outside` says admission belongs
   only to the author tables. So roster rows in a void session still head by
   `#heads-roster`, minus the equivocator's. `session-creator-equivocates-*`
   agrees: Bo's binding is a head.
7. **A deleted creator's row by an equivocator.** `#session-void` defines the
   creator for voiding as the author of that row "not deleted". If the hashing
   row is deleted, the session has no creator and is not void, even if its
   author is an equivocator.
8. **Creator's author-table rows below her creator's row.**
   `#session-from-creator-row` names only the roster tables. The reader leaves
   her author-table rows to the ordinary admission rules.

### The properties, and the defect class

`docs/format-design.md` now opens its seat sections with them, and the rest
is derived from them:

- **P0.** The same rows and headers give the same state in any arrival order.
- **P1.** Adding any signed row, at any seq, by anyone, never removes an
  admitted row or a hold unless that merge reports `AUTHOR_EQUIVOCATED`. Void
  is the only way down.
- **P2.** Equivocation never lets the equivocator choose which of his
  statements survive.

**Every rule on the page that ranks two seqs of one author**, after this step:

| `close-monotone` (R18) | a close that counts against a row of its author in that session at a higher seq | **kept, harmless**: its only outcome is to make that author an equivocator, reported by the merge that makes it true; every row and hold it removes is his own (P1), and none of his statements survives, so he chooses nothing (P2) |
| `parent-forward` (R19) | a parent naming the row's own author against the row's seq | **kept, harmless**: a function of the row alone (malformed or not), the same on every copy in any order; it refuses that author's own row and nothing else |
| `revealing-close` (R18) | the author's rows above the lowest of his closes, to pick revealing headers | **kept, harmless**: decides only which header a report is filed under, never what is admitted or held |

Nothing else on the page orders one author's seqs. (Order by batch id, by
UTF-8 order and the canonical order of `covers` order nothing that decides
admission. `_current`'s tie-break among concurrent heads, by `_r_lc` then
author then seq, is replicated-tables.md's display rule, not on this page.)

**Found, not fixed** (for the property pass; neither is the defect class):

- **P1 and the crossing rules.** A crossing child (`ENTITY_OTHER_SESSION`,
  or a version of another seat) that a copy holds before its parent is
  admitted there, and the parent's arrival removes it, reported
  `SEAT_NOT_HELD` or `ENTITY_OTHER_SESSION`, not `AUTHOR_EQUIVOCATED`. P1's
  letter is broken; only a dishonest writer makes a crossing child.
- **A forward parent naming another author.** R19 covers the row's own
  author. A row naming an id of another author that does not exist yet becomes
  a crossing when that author writes there (the same mechanism as above).
- **D180** (a merge that brings a held row's header without the row is not a
  fixed point) stands; `session-relayed-header-lost-save` records it
  (`stable: false`).

### What was built

- **R14, the declared roster.** `_dai_seat` gains `seats` (the open seats, one
  byte string of 16-byte values) and `close` (`any` or `creator`). The
  creator's seat row declares the roster once; a roster that is not valid
  makes the session void; later versions of that row, and every other
  `_dai_seat` row, count for nothing (no head, nothing declared). A confirm
  counts only for a value the row lists, at any seq. One holder may hold
  several seats. The kit writes the roster from the manifest at session
  creation (`max_parties - 1` open seats; the frame reads `max_parties` from
  the new declaration view `_dai_session_rules`, and the close rule from the
  host, as before). `kit.reseat` and the frame's `session.reseat` are gone;
  `CANNOT_RESEAT` retired. On the creator's copy `confirmSeats` meets a
  contested seat by closing that session and starting a new one, says so
  (`daiKit.onContested`, or its own line) and fires `dai:kit-new-session`
  with `{ session, replaces }`; tic-tac-toe and request move the game or
  request (with its questions) to the new session and offer a "fresh invite"
  button that shares it; the chess fixture does the same through
  `onContested` (`store.restartFrom`), and its `joinActive` no longer picks a
  closed game, so a copy that lost the contest joins the fresh invite's game
  rather than asking again in the old one. The site's seats page and refusal
  table say the same (no reseat; `SIGNED_VIEW_MISMATCH` listed;
  `CANNOT_RESEAT` gone). The close rule is read from the
  creator's seat row by the views and by the frame's close writer.
- **R15.** `sessionIdOf(author, seq, seat, seats, close)`: SHA-256 of the
  author, the seq (eight bytes, big-endian) and the canonical CBOR of
  `[seat, seats, close]` as the row holds them, first 16 bytes; the SQL
  function takes five arguments. `tests/session-id.spec.ts` refrozen (old
  vectors recorded in the file).
- **R16.** `mergeFrom(..., { views })` and `mergeVerified` refuse a sibling
  whose signed-view digest differs: `refused: SIGNED_VIEW_MISMATCH`, nothing
  taken; the refusal is in `src/refusals.ts`, with the opener's sentence in
  `describeMerge`. `manifest.json` beside every vector (per copy: `view`,
  and `session` with `max_parties` and `close`), read by the Python reader.
  The host does not pass the digests yet (host session).
- **R17.** An equivocator holds no seat: a seat whose counting confirms name
  him is void (`_dai_voided`, which now carries `holders`); none of his rows
  is admitted or reported but as his signing twice.
- **R18.** `_dai_close_equivocated`: a close that counts and a row of its
  author in that session at a higher seq, in any table, make him an
  equivocator (`_dai_equivocator` is the headers' and these), revealed by the
  merge that makes it true. `late` gone from admission. The views decide a
  close that counts over a first pass (`_dai_creator0`, `_dai_confirmed0`,
  `_dai_holder0`, `_dai_close0`) that knows only the headers' equivocators, so
  nothing reads itself. The kit writes nothing in a session its own copy
  closed, and `pendingSeat` waits on nothing in a session its creator closed.
- **R19.** `wellFormedParents(text, author, seq)` and `parentsSql`: a parent
  naming the row's own author at a seq at or above its own is malformed.
- **R20.** A session is void when its creator's seat row, deleted or not, is
  invalid or by an equivocator; one holding only a tombstone there admits
  nothing. Reports are made only about rows in a live session.
- **A03.** `_unseated`: a seated row in a live session naming a seat its
  author does not hold, does not wait in, and that is not void, is
  `SEAT_NOT_HELD` (a value no counting confirm names included).
- **A09.** A seat value is a 16-byte byte string; text, NULL, a number or
  another length names no seat; no reader throws.

- **The roster's views, laid out for compile time.** Built as one view per
  step reading the step before, the chain (creator's row, roster, first
  pass, closes, equivocators, live sessions, confirms, voids, holders) was
  inlined into every statement once for each place one step read another:
  `moves_current` on a small vector expanded 1,222 view bodies and took
  109 ms to prepare and run in Node (HEAD: 190 bodies, 11 ms), and the chess
  specs timed out on Chromium. Each public roster view (`_dai_creator`,
  `_dai_holder`, `_dai_closed` and the rest, names and columns unchanged) is
  now one step of the chain and the steps it reads, as common table
  expressions (`roster` and `rosterFor` in `src/replicated.ts`). Lookups are
  uncorrelated `IN`s, and `_dai_holder` groups the confirms once instead of
  reading `_dai_voided`. Now about 21 to 25 ms on that vector (prepare
  dominates; running it is 5 to 6 ms against HEAD's 4). In a session
  document `_current` now reads its `_heads` once, through a materialized
  common table expression, instead of three times (a plain document's
  `_current` is the text it was); 13 ms. That was not enough: the mailbox
  e2e tests on WebKit took 75 s, over 90 s and 82 s where HEAD took 45, 70
  and 53, and a click on the chess board took 1.2 s where HEAD took 0.5.
  Nearly all of it was SQLite compiling reads (a click made about 330 of
  them), and SQLite compiles even a materialized expression once for each
  place that reads it, so no layout of the views got under HEAD.
- **The read helpers keep what they compiled** (`keepReads` in
  `src/runtime/bootloader.ts`): `selectObjects` and `selectArrays` keep the
  64 most recent single read-only statements prepared and reset them after
  use; SQLite re-prepares one if the schema changes. Anything else (a write,
  several statements, other arguments) goes to `exec` as before, so a write
  through a read helper is still seen and saved. Rows and binding are
  exec's. `tests/read-cache.spec.ts` pins that on all three engines. A click
  now takes 60 to 110 ms on WebKit (HEAD 500 ms); the draw path's reads take
  under a millisecond each.
  The first steps (`_dai_roster_value`, `_dai_roster_invalid`, and the first
  pass `_dai_creator0`, `_dai_confirmed0`, `_dai_holder0`) are no longer views:
  nothing outside the chain read them.
- **The inline link cap.** Every document carries its rewritten schema, and
  the request example's inline link went to 36,607 characters against the
  32,768 cap (`arrival-link-state` on Chromium found it). The roster block's
  `--` comments are now dropped when the schema is emitted (they stay in the
  source), each view holds only the steps it reads, with its whitespace
  collapsed, and the request app's own new text was cut. Signed, as the test
  builds it, the request link is 32,683: under, with 85 to spare (HEAD's
  request app, built today, is 32,172; at HEAD it was 31,584). The next growth
  of the request app or the session schema will push it over; the fallback is
  the reference link. Filed as a finding for whoever next touches either.

Page anchors added: `roster-declared`, `creator-row-immutable`,
`session-id-roster`, `document-mismatch`, `equivocator-holds-nothing`,

### Readings taken where the rulings were silent

1. **An equivocator's rows are reported nowhere** but as his signing twice
   (R17 said not admitted; the page now says not reported either, as R9 and
   R10 did for a row at an equivocated id and a void session).
   `session-equivocation-filed` was reworked for it (below).
2. **Reports only in a live session.** A session with no live creator's seat
   row (none held, a tombstone, void) reports nothing, so R20's two copies
   agree whatever row they hold at the creator's id.
3. **The close rule is the creator's seat row's.** The manifest's close is
   what the kit writes there; nothing compares the two (R16 makes two
   manifests unmergeable anyway).
4. **`seats` is one byte string**, the open values one after another, and
   the session id hashes the three columns whatever they hold, so a row whose
   roster is not valid still names its session, which is void.
5. **The counting close R18 reads** is decided over the first pass (headers'
   equivocators only); under `close=any` a holder of the first pass may close.
6. **The kit closes a contested session** before starting the new one, so the
   repair is durable (a reload does not start another) and the asking copies
   see the game closed.
7. **`waiting` excludes a void seat** (it did not before; a row for a void
   seat was already reported nowhere).
