## Step 6: the decisions, before code

Each ruling below is the entry's; what is decided here is how it is built.
Where a probe was run it says so. Probes were scratch scripts outside the
repository, bundled with esbuild and run against `d1614f5`'s `src`.

1. **Names.** "Batch format version 2" wherever the bump is meant:
   `BATCH_FORMAT_VERSION` goes from 1 to 2. The container's `FORMAT_VERSION`
   is untouched.
2. **D161, covers signed.** The canonical header becomes the CBOR array
   `[2, document, author, lc, digest, covers]`, `covers` a CBOR array of
   `[table, seq]` in the order the stored text already uses. The id is the
   first 16 bytes of its SHA-256, so the id commits to the list. The stored
   `covers` column stays, as a cache of the signed list. Verifying has two
   parts. **Authentic:** a list, the stored one or else the list of that
   author's rows naming the id, makes a header that hashes to the id and whose
   signature verifies under a `pub` that fingerprints to the author. Neither
   does: `BATCH_SIGNATURE_INVALID`, naming the author, which is what any
   forgery in her name gets and accuses nobody. **Complete:** every listed row
   found once, and the digest over them is the header's. *Probe 1:* a relabeled
   list fails the signature (no longer a digest mismatch in her name); taking
   the list from the rows naming the id restores the honest header and both
   moves; a relabel with the row's pointer also stripped (a crafted file) is
   refused as a forgery and the row is withheld, which a forwarder could
   always do.
3. **D160 as first ruled, on 2.** Authentic and complete: the rows are taken.
   Authentic and not complete: if another authentic header of the same author
   lists an overlapping `(table, seq)` with a different digest, that is
   equivocation. Both headers are kept, so the evidence travels with every
   copy. The merge reports `AUTHOR_EQUIVOCATED` (the 74th) with the author.
   Admission excludes the overlapping row ids, computed from the headers, so
   they hold whatever order the headers arrive in. *As built:* through
   `_dai_covers`, each header's listings kept by triggers on `_dai_batch`,
   indexed, because a view joining the headers' JSON was unusably slow (see
   the traps). Otherwise
   (a listed row absent) the header is kept, its rows are not taken, and
   nothing is reported: an absent row is someone's withholding, not the
   author's doing. **Why "different digests" at batch level is fair:** an
   honest author never has two headers over one row. A header leaves the
   device only in landed bytes (a share reads the landed copy after
   `flushBeforeLeaving` and `mayLeave`, `currentHtml`; a publish waits for the
   save, D109), and the host signs only above the floor (D105). **F3's second
   assertion predates the ruling** ("Bo's"): it is rewritten to it, both
   copies agreeing that nobody holds the seat, with the report. A third-copy
   test is added (merging from one side alone still sees it).
4. **D134, the key is `(session, entity)`.** In a session table the write
   surface names the session with the entity: `change(table, entity, values,
   session)` and `remove(table, entity, session)`, as `insert` already takes
   it. `writeTargetOf` reads only that session's partition, and an id with no
   session in a session table is refused with a sentence. D135's two-partition
   refusal goes, because nothing is guessed anymore. Chess's `gameById` and
   `active_game_id` name both, and so do the calls in tic-tac-toe and request.
   No byte changes: the canonical row already carries the session.
5. **The frontier retires.** `_dai_close` loses `replica` and `seq`; a close
   is one row carrying its session. `close()` writes one row. check-flag's
   variable-table note for the frontier query goes with it.
6. **D158, the session id names the seat row.** `session = SHA-256(author ‖
   seq)`, first 16 bytes, the seq as eight bytes, unsigned, big-endian, held
   by a frozen vector. `dai_session_id(author, seq)`. `_dai_creator` is the
   `_dai_seat` row whose own `(replica, seq)` hashes to its session, and no
   other. The `nonce` column retires, and no version of that row's entity
   counts. `startSession` stamps the creator's seat row at the seq it named.
   *Probe 3:* **D158's second variant is not closed by this.** A creator who
   left a gap in her seqs signs a confirm there later: the hold moves from Bo
   to Cy, Bo's admitted e5 drops, and nothing is refused. `_dai_holder` takes
   the lowest-seq confirm, which the ruling left alone. Filed as **D165**, for
   a ruling; not in step 6.
7. **Unsigned rows out of every path.** The merge refuses an unsigned row in
   every table (`BATCH_UNSIGNED`), and `SESSION_SYSTEM_TABLES` loses its
   special case. **An arriving database is merged, not mounted:** a file, a
   link with data, or a take is merged in the frame, at open, into an empty
   copy of its own schema, before the application reads it; local tables are
   copied as they are. A resumed copy, and a successor's inherited copy, are
   this device's own and are not re-verified. The compiler refuses a seed
   database holding rows in a replicated table, since nobody signed them.
8. **D108, both directions.** Hosts from before signing respect only
   `requires`, so a replicated build at version 2 lists `authorship` there.
   Those hosts refuse it with `UNSUPPORTED_CAPABILITY`, the most they can do;
   they have no read-only mode to reach. From version 2 on, a host mounts a
   document read-only, with the ruled sentence ("This app needs an update
   before it can be written to; what's here is kept"), when it holds a header
   of a batch format above its own, or when the document is below version 2
   (built without `authorship`, or holding a version-1 header). Read-only is
   the path `refuseWriteRules` already takes: no write rules, and the host
   signs and saves nothing for that mount.
9. **The reference readers level.** Both merge readers keep taking each
   header's signature verdict from the fixture: they check the merge, not the
   curve. Everything after the verdict is theirs to compute: authentic versus
   complete, equivocation voided and reported, unsigned refused in every
   table, `ROW_MALFORMED`, the close without its frontier, and the creator by
   `(author, seq)`. The Python reader's frozen byte vectors (`run.py`,
   `byte_vectors`) gain the version-2 header and the new session id, so its
   encoder is held to the same bytes as the runtime's. Each change gets a
   merge fixture on which a reader that had not made it would disagree.
10. **Order.** The reds first, each run red: the three held `test.fail`s (F3
    rewritten), the third-copy case, and one per change (the version-2 header
    vector, the session-id vector, an unsigned row refused in a plain table,
    an arriving file's forged seat row not counted, a close with no frontier,
    a session-named write, the two read-only mounts, and the refused seed).
    Then the bump, `docs/format.md` rewritten for version 2 with each change's
    reason, both readers, the gate on the exact pushed tree, and the
    verdicts. Then one cold review over the whole bump, then the eighth attack
    review.

## Traps met in the third sitting

- **"Manifest version 4, which this bootloader does not know" is not always
  a stale bundle** (D166). A signed replicated file built at version 4 is
  refused when picked; the specs that pick signed files build at
  `manifestVersion: 3`. Kill 5174 to 5176 first, as ever, but if the sentence
  survives fresh servers, it is D166.
- **A picked file shows a card**: click `#card-open` ("Get") before waiting
  for `loaded`.
- **The app frame appears after `loaded`**, and `appFrame` throws until it
  does, which ends an `expect.poll` at once. Catch inside the poll.
- **The impact map is built from what git tracks.** A new spec checked
  before `git add` reads as "current" locally and stale in CI. Run
  `node scripts/impact-map.mjs --write` (the bare command writes nothing)
  after `git add`, then the typecheck.
- **A view that joins JSON lists is not pushed down.** The first equivocation
  view made a 400-row read take 157 s. Measure any new admission predicate at
  a few hundred rows before trusting it; a derived table kept by triggers from
  its source row, with an index, is the shape that holds.
- **A scratch probe in `tests/` is the fastest page probe** (it gets the
  fixtures and the servers); delete it before the commit. A node probe is
  faster as an esbuild bundle in the scratchpad, importing `src` by absolute
  path.
