### 1. A stamped inline module's `import()` of a remote URL

**It ran.** That is a 3-H1-class defect, now fixed in the policy.

- The test: `tests/shell-channels.spec.ts`, "a stamped inline module cannot
  import() a remote module". It runs in Chromium only. The test starts an
  HTTPS server on `127.0.0.1` with a one-day self-signed certificate made by
  `openssl` (the context ignores certificate errors), and a plain HTTP
  server for the container. The application is one inline
  `<script type="module">` that calls
  `import("https://127.0.0.1:<port>/x.js")`. The test requires the outcome
  "refused" and no request at the remote server.
- Red at `318ebec7` (library rebuilt): `{"outcome":"ran","module":true,"global":true}`.
  The module resolved, its export was read, and its top-level code ran.
- Why: a module fetch carries the nonce of the script that asked for it, and
  a nonce source admits a script whatever its URL. The stamp is not
  involved: the module is inline, sealed, and correctly stamped. Only the
  policy can close this.
- The fix, `src/template.html`: a second
  `<meta http-equiv="Content-Security-Policy">`, enforced alongside the
  first, with `script-src 'unsafe-inline' 'wasm-unsafe-eval' blob:`.
  - It has no nonce, so it admits script URLs by URL alone, and `blob:` is
    the only scheme it names.
  - Its `'unsafe-inline'` only hands inline script to the first policy.
    There the nonce still refuses inline handlers and `javascript:` URLs.
  - It stays second, because `shellNonce()` (`bootloader.ts:220`) and the
    tests read the first meta.
  - The frame inherits both policies.
- Green on the fix: the import is refused and the server sees no request.
  The other two tests in `shell-channels.spec.ts` still pass.
- Pin: `tests/site-claims.spec.ts`, "the no-network sentences hold against a
  stamped module's import()". It holds the making-files sentence ("Code that
  reaches for a CDN … will fail") and requires two things of
  `src/template.html`: the first policy carries the nonce, and a later one
  has exactly `'unsafe-inline' 'wasm-unsafe-eval' blob:` as its
  `script-src`. With the template change stashed, the pin fails.
- Not run: a static `import … from "https://…"` in an inline module. It
  takes the same path (the same nonce on the fetch, the same second policy),
  but only `import()` was run.
