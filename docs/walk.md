# The walk

The walk a person takes with an app: message → useful app content → first
action → saved work → close → same message → continued work. Each flow is
designed here before it is built (ruled 4 October, [backlog.md](backlog.md)).
Each of the seven transitions answers the same five questions. Nothing is
answered yet: the constraints below bind the answers, and the walk itself is
still to be written.

## Constraints on the design

Fixed by rulings before any transition is answered. They bind the design;
they are not the walk.

### Return

From R-B (18 October, [backlog.md](backlog.md)). Return is transitions 6 and
7.

- The person can return on any device. After owner authentication, once,
  the library is there, with every working document the owner holds, and no
  link is needed.
- The link is arrival; the library is home. A link names a document, and
  the person meets it there. Returning does not depend on finding the link
  again. In ruling 2's words: "A delivery opens its app, never a list. The
  library is the owner's home: reached from More, and what owner
  authentication restores on any device. It is never an interstitial on
  arrival."

### Keep

From R-B (18 October, [backlog.md](backlog.md)). Keep is transitions 4
and 5.

- There is no keep sheet. Safari and an installed app are two authors of one
  working copy, so keeping never moves the person from one store to another.
- The working copy's home is the owner's encrypted store; browser storage is
  a cache of it.
