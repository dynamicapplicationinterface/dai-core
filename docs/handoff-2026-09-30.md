**Choices made building them, for a reviewer to move:**

- **The mount's left-floor read is not under the library lock.** A save
  holds that lock while it waits on the mount's write decision, and the read
  is part of that decision, so taking the lock there deadlocks the first
  save. The raise is one compare-and-raise transaction either way. The save's
  and the publish's raises are under the lock.
- **`sealedTopIn` over-counts rather than under-counts.** It takes every seq
  a stored header of the author lists, and every seq of the author's rows
  naming a header the bytes hold, since the signed list is one or the other
  (`verify-lists-tried`). Higher only ever refuses a sign; a pending row
  names no header and does not count.
- **`publishedTop` reads the batch's rows of this author**, not a header
  field: a recipient verifies the header against those rows, so they are what
  it covers. Bytes that are not a batch raise nothing (no recipient takes
  them either).
- **The host refuses to sign a list that repeats a seq**, as well as the
  verifier refusing the header: an honest frame never asks.
- **The sign refused over a seq that left says** "This change reuses a place
  in the document that this device has already sent, so it was not signed.
  Reopen the document to go on." No honest path reaches it.

### What changed, and the anchor for each

1. **Equivocation is keyed by `(author, seq)`, not `(author, table, seq)`**
   (`admit.rs`, `equivocated` and the new `ids`). Two headers of one author
   listing one seq with different digests, in any tables, make the id
   equivocated. Anchors: `#equivocation-any-table`, `#row-seq` ("so
   `(author, seq)` names one row whatever table it is in"), `#equivocated-id`.
   The admitted text still shows one line per table a kept header lists the
   id in; that form comes from the fixtures' README, not the page.
2. **A row is at an equivocated id by its `(author, seq)` alone** (`admit.rs`,
   `is_eq`), so every rule that skips an equivocated row (creator's seat row,
   confirms, closes, heads) skips it whichever table the headers named.
   Anchors: `#session-skip-equivocated`, `#equivocated-counts-nothing`.
3. **A row naming an equivocated id as a parent is neither admitted nor
   reported** (`admit.rs`, new `Verdict::ParentEquivocated`, checked before any
   other rule reads the row's parents). It applies to a parent of any entity,
   and whether or not this copy holds a row at that id. Anchors:
   `#admitted-parent-equivocated`, `#report-silent` ("whatever else it
   meets"), `#session-skip-equivocated` (such a row is not skipped, it is
   silent). Before, the reader skipped the equivocated parent and admitted
   the child.
4. **Two signed rows at one `(author, seq)` in two tables are both taken**
   (`main.rs`, placing). The cross-table collision now refuses only an
   arriving unsigned row; an arriving signed row still displaces an unsigned
   one held in another table. Anchors: `#row-one-id` ("The collision rule
   applies only to unsigned rows"), `#merge-place-rejected`,
   `#merge-signed-outranks`.
5. **A revealing header is found by id, not by (table, seq)** (`main.rs`,
   `AUTHOR_EQUIVOCATED`). An id newly equivocated after the merge is looked for
   in any table of a newly kept header's list; an id already equivocated before
   the merge, now listed in another table, reveals nothing. Anchors:
   `#revealing-two-headers` ("which lists, in any table, a seq of its author
   whose id is equivocated after the merge and was not before it"),
   `#equivocated-third`.

### Silences and ambiguities, with the reading taken

- **An equivocated parent outside a session author table.**
  `#admitted-parent-equivocated` is an admission rule, and admission is defined
  only for a session author table. `#heads-roster` and `#heads-plain` say
  heads are "among rows at ids not equivocated" and say nothing of a row that
  names one as a parent. Reading taken: in the roster tables, the close, and a
  plain document's tables, such a row is counted like any other; its
  equivocated parent is not counted, so naming it hides nothing that shows. No
  vector exercises it.
- **Whether "outranks" crosses tables.** `#merge-signed-outranks` says "at the
  same id", and `#row-one-id` makes the id `(author, seq)` in any table, so the
  reader lets an arriving signed row displace an unsigned row held in another
  table (`merge-seal-cross-table` agrees). The page does not say so in one
  sentence.
- **How a copy knows a row it holds is unsigned.** `#covers-says` says
  `_r_batch` "can be unset on a row that was signed", yet placement asks
  whether the held row is signed or unsigned. Reading taken, unchanged: a held
  row with `_r_batch` NULL is unsigned for placing. The page gives no other
  test a reader can apply to its own copy.
- **Which list a kept header is kept under.** `#merge-headers-kept` keeps a
  header "under the list it signed", and `#verify-lists-tried` lets that list
  be recovered from the rows when the stored one was relabeled. The verdicts
  say only `ok` or `incomplete`, not which list verified, so this reader reads
  the stored `covers` for what a header lists. A vector whose header verifies
  only through the recovered list would expose a reader that does this; none
  does.
- **Whether a copy's own held headers are authentic.** `#equivocation` needs
  two authentic headers; the local copy's own headers are never verified by a
  merge. Reading taken: every header a copy holds counts toward equivocation.
- **The counts and the dump.** `#merge-counts` defers them to
  replicated-tables.md, section 8, which this level was barred from reading;
  the reader's existing dump and counts were kept as they were and the
  fixtures held them.
- **The form of the admitted text** (one `# equivocated` line per table) is in
  the fixtures' README only; the page does not define it.
