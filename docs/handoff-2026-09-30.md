**How a filing is witnessed.** `refusedBatches` shows an author and a code,
not the id a report is filed under, so a filing can be seen only in the

reported `SEAT_NOT_HELD`), sealed alone, whose header id the generator finds

since an id hashes the header and not the signature) so that it sorts
between the right filing and the wrong one. Each such vector asserts the
order it needs.

**The whole-digest hold-out is an approximation.** A reader that compares
the row at an id rather than the whole batch cannot be written from the
headers alone, since a copy holds one row at an id in a table. The hold-out
treats two headers that list a seq in one table, with different lists, as
differing in another row and so not equivocation at that seq. The vector
(two headers, one over the row alone and one over it and a second row, the
row the same on both copies, which the generator asserts) fails it.

### Silences and ambiguities, with the reading taken

- **An equivocated parent outside a session author table.**
  `#admitted-parent-equivocated` is an admission rule, and admission is defined
  only for a session author table. `#heads-roster` and `#heads-plain` say
  heads are "among rows at ids not equivocated" and say nothing of a row that
  names one as a parent. Reading taken: in the roster tables, the close, and a
  plain document's tables, such a row is counted like any other; its
  equivocated parent is not counted, so naming it hides nothing that shows. No
  vector exercises it.
- **Whether "outranks" crosses tables.** `#merge-signed-outranks` says "at the
  same id", and `#row-one-id` makes the id `(author, seq)` in any table, so the
  reader lets an arriving signed row displace an unsigned row held in another
  table (`merge-seal-cross-table` agrees). The page does not say so in one
  sentence.
- **How a copy knows a row it holds is unsigned.** `#covers-says` says
  `_r_batch` "can be unset on a row that was signed", yet placement asks
  whether the held row is signed or unsigned. Reading taken, unchanged: a held
  row with `_r_batch` NULL is unsigned for placing. The page gives no other
  test a reader can apply to its own copy.
- **Which list a kept header is kept under.** `#merge-headers-kept` keeps a
  header "under the list it signed", and `#verify-lists-tried` lets that list
  be recovered from the rows when the stored one was relabeled. The verdicts
  say only `ok` or `incomplete`, not which list verified, so this reader reads
  the stored `covers` for what a header lists. A vector whose header verifies
  only through the recovered list would expose a reader that does this; none
  does.
- **Whether a copy's own held headers are authentic.** `#equivocation` needs
  two authentic headers; the local copy's own headers are never verified by a
  merge. Reading taken: every header a copy holds counts toward equivocation.
- **The counts and the dump.** `#merge-counts` defers them to
  replicated-tables.md, section 8, which this level was barred from reading;
  the reader's existing dump and counts were kept as they were and the
  fixtures held them.
- **The form of the admitted text** (one `# equivocated` line per table) is in
  the fixtures' README only; the page does not define it.
