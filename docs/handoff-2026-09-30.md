**F1, the floor, as ruled at the start of the sitting.** Two marks, both
beside the person key in the key store, kept when a document is removed:

- **The sequence floor** (`dai:seq-floor:`), as before: every seq the device
  issued a row at, so no new row takes one again. A sign now claims it from
  the seqs the header lists, decoded by the host from the bytes it signs;
  the `seq` the frame sends beside the header is no longer read (the bridge
  message is unchanged, and the frame's comment says so).
- **The left floor** (`dai:left-floor:`, new, `src/keys.ts`): what
  `docs/format.md` calls the floor, the highest seq a header of this
  device's lists in bytes the host saw land in its store or is about to
  publish, read in the host's own engine. A sign listing any seq at or below
  it is refused (`ALREADY_LEFT`), in the same transaction as the sequence
  floor's claim. Raised: by a save, after the write and the library record
  land and before the frame hears the save landed (so before any publish);
  by a publish, from the rows of the batch about to leave, before it is
  sealed for the relay; and at mount, from the stored copy, for a copy that
  came from this device's store (not an arrived database). The mount's read
  closes the crash between "landed" and "raise left".
- **Red first.** At the previous host: a header over a seq that had left was
  signed (a probe with the left-floor poll removed showed `signed` where the
  test wants `refused`); no left floor was kept; the crash test found no

**F2.** `parentsSql(text)` is the shape check in SQL, a `CASE` so

**R8.** Red first: at the previous runtime the vector's generator `expect`
failed ("refused [], not Ada's header alone as BATCH_SIGNATURE_INVALID"),
both rows were taken and the two directions converged. It is the first
fixture whose `verdicts.json` carries a refusal code (Pass 2's
`fixtures-verdicts` LOW). The Python reader needed no change: it takes the

generator asserts the header it builds lists `[["cases",1],["notes",1]]`.

**Choices made building them, for a reviewer to move:**

- **The mount's left-floor read is not under the library lock.** A save
  holds that lock while it waits on the mount's write decision, and the read
  is part of that decision, so taking the lock there deadlocks the first
  save. The raise is one compare-and-raise transaction either way. The save's
  and the publish's raises are under the lock.
- **`sealedTopIn` over-counts rather than under-counts.** It takes every seq
  a stored header of the author lists, and every seq of the author's rows
  naming a header the bytes hold, since the signed list is one or the other
  (`verify-lists-tried`). Higher only ever refuses a sign; a pending row
  names no header and does not count.
- **`publishedTop` reads the batch's rows of this author**, not a header
  field: a recipient verifies the header against those rows, so they are what
  it covers. Bytes that are not a batch raise nothing (no recipient takes
  them either).
- **The host refuses to sign a list that repeats a seq**, as well as the
  verifier refusing the header: an honest frame never asks.
- **The sign refused over a seq that left says** "This change reuses a place
  in the document that this device has already sent, so it was not signed.
  Reopen the document to go on." No honest path reaches it.

### Left, for the cold review

- **A leave that does not raise the left floor.** The shell's own file write
  (a download or a picker save) asks `LEAVE_CHECK` about the frame's bytes,
  which can hold a header whose save never landed. Those bytes leave the
  device and the left floor does not count them. A re-seal after that save is
  lost, of rows a landed save held pending, would sign a second header over a
  seq that left. Narrow (a race, then a lost save, then a file written in
  between), and outside the three routes ruled (save, publish, mount). The
  host's own exports read the landed store copy and are counted already.
- **Cost.** Every read of a row's parents now runs the shape check first, in
  the heads walk among them; measure it with the heads at size, beside
  `namesEquivocated` (the heads view's own cost note).
- **The bridge still carries the frame's `seq`** on a sign, unread by the
