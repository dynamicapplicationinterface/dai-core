## Traps met this session

- **A "known red" can be a race.** Read which tests failed on CI by name before
  believing the handoff's list: the two named reds passed there, and the real red
  was one nobody had named.
- **The rename target existed.** A rename onto a file that is already there is
  an overwrite; look first.
- **Error context quotes the test.** A grep hit in `error-context.md` can be the
  test's own source excerpt, not the page; read the page's text through the test.
- **A fix can open the door it was built to close.** The repair's first source
  (the address) was the one input anybody can write. Ask of every new input to a
  key path: who else can write this?
- **A relaunch change presses every iPhone test, and the local tier runs none.**
  The chromium + node gate cannot see the iOS path; `a20cb76`, pushed under
  `e313d12`, had run only `invite-identity` on WebKit, and CI found the cost in
  `launch-address`. Before pushing a launch-path change, run on WebKit every
  spec that reaches the relaunch (`grep -l "iOS reload" tests/`), and compare
  any failure with the baseline before believing it either way.
- **A fixed sleep before an absence check** proves nothing: wait for the decision
  point (here, the mailbox starting or the opener saying it has no key).
