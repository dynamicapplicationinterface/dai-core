## Build 2b-2e

Branch `build/library-reads`, a draft PR against `main` (D296), not merged.
Four items: the production store's deploy, recorded; and three of D308's
decision paths, each told a library read that did not answer from one that
answered without the document. For the person using the app: a library that
could not be read for a moment no longer forgets the document they had open,
signs them out of an owner, or restores a kept copy over a document that may
be held here; the opener says the library could not be read and changes
nothing, and the next load or the next Recover does what it would have done.

### Rulings built

Ruled 1 November:

- **The resume on load** (D308): "a library read that fails or does not
  answer says nothing about what is held; the resume key is forgotten only
  when a read ANSWERED with no such document. On a failed read the load
  behaves as a load with nothing to resume for this load only (the chooser),
  keeps the key, and says in the console why."
- **`letGoOfOwner`** (D308): "the owner is let go only when the library read
  ANSWERED; a read that fails or times out leaves the
  owner record and the sign-in as they are, and the caller says the sentence
  for a failed read (reuse an existing failed-read sentence if one fits;
  otherwise "The library could not be read, so nothing was changed. Try
  again.") in the one note row, never OWNER_LET_GO_SAID." Amended from
  "ANSWERED with an empty list" on the review of items 1–4 (O1, below): read
  literally, an owner the store can never register would stay signed in for
  good whenever a document is held here, every save refused, which is what
  D302 lets go of.
- **Recovery's `held` and `snapshot`** (D308): "a failed record read during
  restore is not "not held here": that document is neither restored over nor
  adopted; it is reported with the cut-short path's words ("could not be
  reached") naming the document, the rest of the library goes on, and
  nothing is written for it."

How each was read where the words left a choice:

- **"Answered with an empty list"** was read as "answered", and the ruling's
  words are now amended to match (O1): the list a read answers is what
  `letGoOfOwner` gives back to this browser, so a list that names documents
  gives them back and then lets the owner go, as before. What the ruling
  takes away is the let-go on a read that did not answer.
- **The sentence for item 3** is the new one, not `LIBRARY_UNREAD` ("The
  library could not be read. Try again."), which answers a tap the person
  made. At a mount the person asked nothing, so the sentence says that
  nothing changed.
- **Item 4's record** is a list of its own in the outcome (`unread`), not an
  entry in `refused`: every sentence counts `refused` as "a kept copy could
  not be verified", which a document whose record here was not read is not.
  The document is named by the title of its kept copy, read and verified at
  the store as a restore would and never written (`verifyOne`, split from
  `restoreOne`); when that does not verify or the store does not answer, it
  is "a document". The owner's record stays marked recovering while any
  document is unread, so Recover and Finish recovering bring it later.
