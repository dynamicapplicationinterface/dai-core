## The rulings for the next session (in the entries' status lines)

- **D159, as proposed:** `_r_parents` must be a flat JSON array of
  `"<32 hex>:<integer>"` strings, with a length cap; anything else is refused
  at merge as `ROW_MALFORMED`, its own code (the registry holds 72 today, so
  it is the 73rd), so the report says what it was.
- **D160, void both and report:** two valid signed batches from one author
  covering the same `(table, seq)` with different digests are equivocation.
  Once a copy has seen both, neither row counts, and the merge reports
  `AUTHOR_EQUIVOCATED` (the 74th) with the author. Copies converge once both
  rows reach them; before that they differ, which is honest. **How, also
  ruled, on D160:** no new storage. Equivocation is a condition on
  `_dai_batch` (two verified headers from one author covering one
  `(table, seq)` with different digests), computed at admission. A run found
  one gap, written there: a forwarded header whose row the forwarding copy
  lacks is refused as `BATCH_DIGEST_MISMATCH` downstream, so the build checks
  the signature first and keeps such a header as evidence.
- **D158, bind the session id to the row, not the nonce:**
  `session = SHA-256(creator author id ‖ creator seq)`, the seq being the
  seat row's own. `_dai_creator` is exactly the row that `(author, seq)`
  names; any other seat row of hers, backfilled or not, holds nothing. No
  highest-seq rule (it would refuse honest out-of-order delivery by file). A
  format change: it lands in step 6's bump, and its `test.fail` names step 6.
- **On D80:** every high in the seventh review came from the creator's own
  later rows. The creator is the last unbounded author in the model, and
  D158 bounds her. Step 5 closes on the eighth review, told the same
