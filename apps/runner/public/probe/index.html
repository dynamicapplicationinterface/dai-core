Device probe

Two measurements for the relay work: whether a key survives here, and whether one passkey gives the same secret however it is reached. Nothing here is sent anywhere.

Where this is running

1 · Does a key survive

A non-extractable P-256 private key in IndexedDB. Come back in fourteen days without clearing anything and see whether it still signs.

Leave this site alone until then. Not just this page — opening anything on opendai.app counts as a visit and restarts the clock for whichever context you opened it in. Both the browser and the installed app have to sit untouched, so route any real use through the desktop host or another browser until the fortnight is up.

2 · Is the passkey secret the same everywhere

Register once, then evaluate from every route that can reach the same credential — this device, a phone by QR code, a security key. The input is fixed, so the output must not move. A row that differs from the first row for the same credential is the finding.

Run the QR route from Chrome as well as Safari, and say which in the label. A value that moves in Safari alone is a WebKit bug and a browser caveat; a value that moves in both is a protocol divergence, and the exclusion stops being about Safari.
